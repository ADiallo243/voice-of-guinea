New features default to **disabled**. Source code existing is not proof of a live integration.

1. Run `npm ci`, `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`, and `npm run test:e2e` from `voice-app`. Browser tests run dedicated local servers on ports 43873/43874; install Chromium with `npx playwright install chromium` first. They use explicitly enabled demo content and isolated UI fixtures, never production drafts or subscriber addresses.
2. Review and apply `supabase/migrations/20261115010644_naya_reading_assistant.sql` after existing migrations 001–012. The migration was tested in isolated PGlite PostgreSQL with authorization roles; it has not been applied to hosted Supabase. Verify the hosted schema, service-role grants, indexes, and RLS with Supabase advisors. Existing numbered migration history must be reconciled before using automated CLI migration push.
3. Stage the existing Vercel application with root directory `voice-app`, keeping all three new flags false. Verify real published content, staff login, article save/publish, newsletter confirmation and unsubscribe against a consented test inbox. Provider configuration presence alone does not prove delivery or successful authentication.
4. Configure `OPENAI_API_KEY`, `NAYA_MODEL` (default `gpt-4o-mini`), a strong independent `NAYA_RATE_LIMIT_SECRET`, and optional `NAYA_DAILY_LIMIT` (default 5, maximum 20) / `NAYA_GLOBAL_DAILY_LIMIT` (default 1000, maximum 10000). Verify the chosen model is accessible and supports Responses API structured output. Put all values in server-only environment variables.
5. Enable `NAYA_SUMMARIES_ENABLED=true` in staging. Publish/save a consented test article and verify draft generation without blocking the publishing response. Summaries are generated once for each normalized title/deck/text hash. Images and whitespace-only changes do not change the hash; wording changes conservatively require renewed approval. Do not generate on article page views.
6. As an active owner/editor, open the article editor's **Naya · Validation éditoriale** panel. Preview/edit three points, approve, reject, regenerate, or disable Naya. Rejected/error summaries may be regenerated. An approved summary must be rejected before regeneration; processing claims may be retried after two minutes. Reload after generation. Previously published articles require a save or an explicit editorial generation; there is no automatic paid backfill.
7. Enable `NAYA_CHAT_ENABLED=true` in staging only after checking real grounded answers, follow-ups, unsupported questions, breaking-news uncertainty, injection attempts, provider failure, quota exhaustion and article-level opt-out. There is no web browsing or database tool available to the model. Current-article references are local links; source URLs alone are not treated as retrieved supporting text. Automated UI tests mock AI replies and do not establish real model factual quality.
8. Verify newsletter sending with the existing Resend account and a verified `NEWSLETTER_FROM_EMAIL`. The shared form now stores **pending** subscriptions, sends a confirmation link, and activates only after confirmation. An active duplicate does not rotate tokens or send mail. Campaigns must include each recipient's existing unsubscribe flow; no daily digest scheduler was found or added. Complete an actual send/receive/confirm/unsubscribe test before enabling `NEWSLETTER_POPUP_ENABLED=true`.
9. Promote only after those staging checks pass. Run live health checks. No production release was performed during this implementation.

## Privacy and quotas

Chat text is kept in React memory for the current page, not in the application database. At most eight previous messages are submitted. OpenAI requests use `store:false`; provider abuse-monitoring retention and account-specific policies still require verification. Avoid entering sensitive personal data. Feedback sends only a rating to existing Google Analytics after valid audience consent. Do not add email addresses or question text to analytics parameters.

Quotas use daily HMAC fingerprints of the deployment proxy's client IP; shared networks can share the five-question allowance. Vercel's trusted forwarding header takes precedence. Do not deploy this endpoint behind an untrusted proxy that allows caller-controlled forwarding headers. A server-side global daily cap limits aggregate cost. Quotas are charged before provider invocation, including failed requests, to bound abuse. The existing daily publication cron removes usage rows older than 48 hours while chat is enabled; keep that cron operational and run the same cleanup after permanently disabling chat.

The newsletter invitation appears only on article routes after 35 seconds and 50% page scroll, at most once per browsing session. It waits while a consent banner, another dialog, Naya, or form/button focus is active. Dismissal suppresses it for 30 days. A requested or confirmed subscription suppresses it locally. Browser storage failure suppresses the invitation. It does not promise daily mail. Native dialog provides focus containment and Escape dismissal; focus returns on close. Turnstile uses explicit rendering so later-mounted forms work, with widget reset after a submission result.

## Analytics

In the existing GA4 property, use **Reports → Realtime** or **Explore → Free form** with Event name / Event count. Newsletter funnel: `newsletter_popup_shown` → `newsletter_form_submitted` → `newsletter_confirmation_requested` → `newsletter_subscription_success`. Success denotes the browser's confirmation-page result, not a proven campaign delivery. Naya events cover open, summary view, question submission, completed/error response, and feedback. Article views, related clicks and search submission use existing consent. No new analytics provider is installed. Consent rejection prevents these custom events.

## Rollback

Turn the three flags false and redeploy to stop AI calls and invitations. Revert the code release using the prior Vercel deployment if needed. Retain the additive Naya tables and approved records; the old app ignores them. Do not drop tables or editorial records as a routine rollback. Reverting newsletter code restores its previous immediate activation behavior, so prefer disabling the invitation and fixing the confirmation path over reverting that safety fix.
